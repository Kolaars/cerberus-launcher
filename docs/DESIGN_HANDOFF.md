# Handoff дизайнеру

Этот документ — карта интерфейса для гейм-дизайнера. Задача каркаса: дать работающую логику и
чистую визуальную структуру, которую можно заменить макетом без переписывания React-кода.

## 1. Как посмотреть текущий интерфейс

```bash
npm install
npm run dev
```

- F12 открывает DevTools (только в dev-режиме).
- Окно можно растягивать; минимальный размер — `980 × 640`. Проверяйте макет на этой ширине.
- Все страницы доступны из левого сайдбара; навигация хэш-роутингом (`#/settings` и т. п.).
- Для проверки состояний без реальной установки можно менять данные в DevTools React
  (вкладка Components) или временно править мок-состояние в `LauncherContext`.

## 2. Каркас экрана

```text
┌──────────────────────────────────────────────────────────────┐
│ TitleBar 46px: лого, название, версия, свернуть/развернуть/× │
├───────────────┬──────────────────────────────────────────────┤
│ Sidebar 232px │ Content: скролл, max-width 1220px, padding 28│
│               │                                              │
│ Навигация     │  PageHeader: eyebrow / title / description   │
│ ...           │  ┌────────────────────────────────────────┐  │
│ Java status   │  │ Panel / таблица / форма                │  │
│ Аккаунт       │  └────────────────────────────────────────┘  │
│ Версия        │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

- Шапка окна — часть Electron-окна, не HTML-браузера. Высота задаётся
  `--titlebar-height: 46px`; менять её можно, но перетаскивание окна привязано к
  `.titlebar` (`-webkit-app-region: drag`).
- Кнопки окна находятся в `.titlebar__controls` с `-webkit-app-region: no-drag`.
  Любые новые интерактивные элементы в шапке тоже должны получить `no-drag`.
- Сайдбар фиксированной ширины `--sidebar-width: 232px`, скроллится отдельно.
- Контент скроллится внутри `.app__content`; страница не должна создавать второй вертикальный
  скролл.

| Токен | Шрифт |

| `--font-display` | Segoe UI Variable Display (заголовки) |

Размеры:

## 4. Компоненты и классы

Все компоненты — в `src/renderer/src/components/`. Классы заданы в `components.css`.

### Кнопки `.btn`

| Класс | Когда использовать |
| --- | --- |
| `.btn--primary` | Главное действие: играть, установить, войти, сохранить. |
| `.btn--secondary` | Альтернативное действие: обзор папки, выбрать аккаунт, обновить. |
| `.btn--ghost` | Третичное действие: открыть папку, отмена, ссылка. |
| `.btn--danger` | Необратимое удаление (обычно в модалке). |
| `.btn--small` | Компактные действия в таблицах/панелях. |
| `.btn--hero` | Большая кнопка запуска на главной (54px). |

Состояния: `hover`, `active`, `:disabled` (прозрачность 0.45), `:focus-visible` (обводка
акцентом). Иконка внутри кнопки — inline SVG 15–22px.

### Поля

- `.input`, `.input--mono`, `.input--search`, `.input--invalid`, `.textarea`.
- `.field` — подпись + поле + подсказка; `.field__row` — подпись и значение в строке.
- `.range` — слайдер памяти; стилизован под тёмную тему.
- `.switch-field` — переключатель снапшотов; чекбокс скрыт, визуал — `.switch-field__track`.
- `.path-field` — input/select + кнопки «Обзор/Открыть».

### Статусы и данные

- `.badge` + `--success` / `--warning` / `--accent` / `--outline`.
- `.status-dot` + `--starting` / `--running` / `--stopping` / `--error` / `--exited`.
- `.progress` + `.progress__fill` — прогресс установки.
- `.spinner` / `.spinner--small` — загрузка.
- `.avatar` — скин (`.avatar--skin`), инициалы (`.avatar--initials`), пустой (`.avatar--empty`).

### Контейнеры

- `.panel` — базовая карточка; `.panel__head` — заголовок и действие.
- `.callout` + `--info` / `--error` — подсказки и ошибки.
- `.empty-state` — пустые списки.
- `.modal-backdrop` / `.modal` — подтверждение удаления.
- `.toasts` / `.toast` — уведомления справа снизу.
- `.console` — раскрывающаяся консоль логов (`.console--open`).

### Навигация

- `.titlebar`, `.window-button`, `.window-button--close`.
- `.sidebar`, `.nav-item`, `.nav-item--active`, `.account-chip`, `.sidebar__status`.
- `.page-header`, `.eyebrow`, `.page-title`, `.page-description`, `.page-header__actions`.

## 5. Экраны и состояния

### «Играть» (`pages/PlayPage.tsx`)

- Hero с крупным заголовком, аккаунтом, выбором версии и главной кнопкой.
- `.hero__emblem` — место для ключевого артворка; скрывается уже 1040px. Размер 250×250.
- `.stat-grid` — 4 карточки: установлено версий, последний релиз, Java, папка игры.
  На ширине < 1180px становится 2×2.
- `.install-panel` — прогресс установки с названием стадии.
- `.launch-panel` — состояние запуска, кнопка «Остановить».
- `.console` — логи; раскрывается автоматически при запуске игры.
- `.callout--info` — приглашение добавить аккаунт.
- `.page-footnote` — память и снапшоты.

Состояния: нет аккаунта; нет версий; идёт установка; игра запускается/работает/остановлена/
ошибка; консоль свёрнута/раскрыта.

### «Версии» (`pages/VersionsPage.tsx`)

- Заголовок с кнопкой обновления.
- `.inline-progress` — компактный прогресс установки.
- `.toolbar` с `.filter-tabs` (Все/Релизы/Снапшоты/Установленные) и поиском.
- `.version-table` — пять колонок: версия, тип, дата, статус, действия. На узком окне дата
  скрывается.
- Для установленной версии — «Играть» + удаление; для остальных — «Установить».
- `.empty-state` при пустом результате.
- Модалка подтверждения удаления.

Состояния: загрузка списка (сейчас просто пустой список + кнопка «Обновляем…»), ошибка сети,
пустой поиск, идёт установка, снапшоты выключены.

### «Модпаки» (`pages/ModpacksPage.tsx`)

Статичная страница-заглушка: баннер «скоро», 4 карточки roadmap, справка о готовых контрактах.
Место под будущий список инстансов — после баннера.

### «Аккаунты» (`pages/AccountsPage.tsx`)

- `.profile-panel` — активный профиль, аватар 92px, бейджи Microsoft/офлайн и UUID.
- Список аккаунтов с выбором и удалением.
- `.auth-panel` — Microsoft:
  - нет Client ID → настройка;
  - готово → кнопка входа;
  - device flow → крупный `.device-code`, ссылка, статус, отмена;
  - ошибка → `.callout--error`.
- Офлайн-форма: ник 3–16 символов, валидация.
- `.panel--muted` — блок безопасности.

### «Настройки» (`pages/SettingsPage.tsx`)

Две колонки на широком окне, одна на узком:

1. Папка игры + переключатель снапшотов.
2. Java: текущая версия, select обнаруженных, ручной выбор.
3. Память и JVM: слайдер 1–32 ГБ, текстовое поле аргументов.
4. Microsoft: Client ID, ссылка на документацию.
5. О приложении: версии Electron/Chromium/Node/Java и пути с кнопками «Открыть».

Внизу `.settings-footer` — индикатор несохранённых изменений и кнопки «Сбросить/Сохранить».

## 7. Правила замены визуала

1. **Сначала токены, потом CSS-классы.** Цвета, радиусы, тени и метрики меняются в
   `tokens.css`; это автоматически обновляет все экраны.
2. **Не меняйте имена классов без правок компонентов.** Селекторы завязаны на текущую
   разметку. Если нужен новый класс — добавьте его в CSS и в компонент.
3. **Не удаляйте `-webkit-app-region: drag`** у `.titlebar` и `no-drag` у кнопок: иначе окно
   перестанет перетаскиваться или кнопки перестанут нажиматься.
4. **Сохраняйте `:focus-visible`.** Это единственная видимая навигация с клавиатуры.
5. **Не уменьшайте контраст мелких подписей** ниже текущего: 10–11px текст должен оставаться
   читаемым на `--bg-surface`.
6. **Не добавляйте второй скролл.** Контент скроллится в `.app__content`.
7. **Иконки — inline SVG** с `stroke="currentColor"`. Новые иконки складывайте в
   `components/Icons.tsx`, чтобы сохранить единый стиль (1.8px stroke, 24×24 viewBox).
8. **Адаптив обязателен.** Проверяйте 1200×800, 980×640 и промежуточные ширины; ключевые
   breakpoints — 1180, 1120, 1040, 860px.
9. **Тексты — на русском** и вынесены в JSX. Если появится i18n, строки нужно будет извлечь;
   пока используйте короткие формулировки, помещающиеся в кнопки.
10. **Не трогайте логику IPC и сервисов.** Дизайн-правки не должны менять `LauncherContext`,
    `preload`, `main` и `shared`.

## 8. Чего не хватает для полноценного макета

Это подсказки, а не обязательные требования:

- Скелетоны загрузки списка версий вместо мгновенного empty-state.
- Отдельный экран/состояние «первый запуск» с настройкой Client ID и Java.
- Иллюстрации для пустых состояний (сейчас — универсальные иконки).
- Дизайн модовых загрузчиков и карточек модпаков (сейчас только roadmap).
- Состояние «обновление лаунчера» и экран ошибки соединения.
- Тёмная/светлая темы: токены готовы к переключению, но светлая палитра не проработана.

## 9. Чек-лист перед передачей макета

- [ ] Все цвета/радиусы/тени выражены токенами или новыми классами, без случайных inline-стилей.
- [ ] Проверены hover, active, disabled, focus-visible для кнопок и полей.
- [ ] Проверены пустые, загрузочные и ошибочные состояния каждого экрана.
- [ ] Проверена ширина 980px: таблица версий, настройки, аккаунты не ломаются.
- [ ] Шапка окна остаётся перетаскиваемой, кнопки окна кликабельны.
- [ ] Консоль и длинные пути/ники не выходят за границы (truncate/ellipsis).
- [ ] Все интерактивные элементы доступны с клавиатуры и имеют `aria-label`, где нет текста.
- [ ] Иконки и артворк не растянуты и не размыты при 1×/1.25×/1.5× масштабе Windows.
- [ ] `npm run typecheck` и `npm run build` проходят после правок.
